# Opcode Implementation Status — At a Glance

This document is a **consolidated status overview** of every opcode in the DofusArena wire
protocol and its current state in the Go server. It is generated by scanning
`internal/protocol/opcodes.go`, the handler registrations in `internal/dispatch/`, and the
packet builders in `internal/dispatch/packets_*.go` / `internal/combat/`.

For the byte-exact payload of each opcode, see the per-domain files in this same folder
(`01-connection-auth.md` … `08-fight-combat-engine.md`).

## Status legend

| Status | Meaning |
|---|---|
| **Implemented** | Has a real handler (Recv) or is actively emitted by a builder (Send). Client and server agree on the wire format. |
| **Partial / hardly usable** | Registered/emitted but with a known gap: stub logic, empty payload blobs, or a flagged wire mismatch. Usable only in a limited path. |
| **Not implemented** | Opcode is defined in the protocol but the Go server has no handler/builder for it. |
| **Not wired** | Defined for protocol completeness but neither the legacy Java server nor the Go server ever send/handle it (dead code on both sides). |

## Notable caveats

1. **Routing is table-based, not a switch.** The router (`internal/dispatch/router.go`) uses a
   `map[protocol.RecvOpcode]HandlerFunc`. Unregistered opcodes are a silent debug-level no-op by
   design, which is what allows the server to be partially implemented during the port.
2. **No remaining Recv gaps in this domain:** the right-click "challenge player" flow
   (`RecvFightInvitationRequestMessage` 4301 + accept 4305 / reject 4307) is now fully implemented
   in the Go server — a Go-only completion of what the legacy Java server left as a `TODO` stub.
   See `docs/opcodes/04-matchmaking-invitation.md`.
3. **Admin-console opcodes (8193–8195) are now implemented** (`internal/dispatch/handlers_admin_console.go`,
   `packets_admin_console.go`). Correcting an earlier assumption: the client's `ConsoleAdminCommand`
   (8193) is an `OutputOnlyProxyMessage` sent over the *regular game socket*
   (`DofusArenaGameEntity.getNetworkEntity().sendMessage`), so it is a **client→server** opcode
   (`RecvConsoleAdminCommand`), despite the legacy `OpCode.java` listing it in the Send enum. The
   server replies with `CONSOLE_ADMIN_COMMAND_RESULT` (8194) TRACE/LOG/ERROR console lines and a
   `DEFAULT_RESULT` (8195) completion code. Access is gated by `sessionIsAdmin` (the same
   `Account.IsAdmin` flag used by the GM chat commands and web portal) and every attempt is logged.
   The initial command set is `HELP`, `STATUS`, `PING`, with an easy extension point in the
   `adminCommands` table. The *separate* SSL `AdminServerInstance` subsystem (its own
   `LoginMessage`/`PropertyQuery` protocol for live subsystem-property queries) remains out of scope.
4. **GM commands** (`/TP`, `/CARD`, `/ALLCARDS`, `/CELLID`, `/STATS`, `/PRES`, `/CANCEL`,
   `/APPEAR`) are text commands parsed inside the vicinity chat handler
   (`handlers_gm_commands.go`), gated on admin permission — not opcodes themselves.
